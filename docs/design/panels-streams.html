Panels, and where the JSON goes

One command, gdoc help publish, run three ways. Every line carries a tag in the left margin that names the stream it came from. The tag is part of this page only, not of the terminal.

Two outputs, not one

Every program on macOS and Linux has two separate outputs. They are like two pipes leaving the same machine.

stdout the answer

The result of the command. Other programs read it.

  • gdoc prints exactly one JSON object here, always.
  • Skills and the AI read this object.
  • Panels does not touch it.

stderr words for a person

Messages around the result: help text, progress, the login link, errors.

  • On a terminal, gdoc can draw it with boxes and colour.
  • On a pipe, gdoc prints it as plain text.
  • Panels changes only this, and only on a terminal.

A terminal shows both pipes on the same screen, one after the other. That is why they look like one output. A pipe, a file or | jq pulls them apart.

1. You type it in a terminal

stderr is a terminal, so gdoc draws Panels. stdout is a terminal too, so the JSON line appears under the panels, as it does today under the plain help.

~/hub, zsh, 82 × 24

The status bar shows version, channel and token time. It has no account name, because gdoc cannot know it offline.

2. A skill or the AI runs it

When Claude runs a command, both outputs are pipes, not a terminal. We measured this in this session: [ -t 2 ] answers "pipe". So gdoc prints the plain help, exactly today's text, and no Panels at all. The AI receives the two outputs separately:

3. You pipe the answer into jq


| takes stdout only. stderr still goes to your screen. So you see Panels, and jq gets the JSON and prints what you asked for.
