## Context (from discovery)

- `go/internal/body/mark.go` is the `==text==` extension: a delimiter pair
  producing a `*Highlight` inline node. `inline.go:102` folds it into
  `Run.Highlight`, a string, and `build.go:273` turns that into
  `w:highlight w:val="yellow"`, one of Word's sixteen named highlights.
  `TestAMarkedSpanIsItsOwnNodeKind` is its pin. An emoji at the start of the
  highlight is today ordinary text inside it.
- Obsidian 1.14's changelog: "Add a color emoji (🔴, 🟠, 🟡, 🟢, 🔵, 🟣) to
  the start of a highlight to change its color." Six emoji, one position.
- `runOpts` in `build.go:75` carries `Color` and `Highlight` already;
  `addRuns` writes `w:color` for a colour and `w:highlight` for a highlight.
  There is no `w:shd` on a run anywhere in the package, and no `w:rStyle`.
- goldmark ships no bracketed-span extension. Pandoc's grammar: `[` inline
  content `]` immediately followed by `{` attributes `}`; a `[` not followed
  by `]{` is ordinary text, as it is in a link, and `[words](url)` must stay
  a link. This milestone reads exactly one attribute, `.pencil`.
- `go/internal/render/styles.go` writes nine paragraph styles from
  `house.yaml`'s `styles:` and no character style. M18 adds the first one,
  `FootnoteReference`, so by the time this runs there is a writer to extend.
- `go/internal/house/house.yaml` carries `highlight_yellow: '#FFFF00'` under
  `palette:` for the cover's placeholders; `render/front.go:55` writes them
  with Word's named yellow. Untouched here.
- `go/internal/docs/walk.go` reads no `textStyle.backgroundColor` and no
  `foregroundColor`: `docs.Run` carries kind, text, indices, suggestion ids,
  link and chip detail. Export cannot see a colour until the read keeps it.
- `go/internal/export/project.go:96` calls `view.Project` with options; the
  Markdown a tab becomes is `view`'s. A mark written on export is written
  there under an option export passes and read does not.
- `body.Counts` reaches both envelopes: `cmd/gdoc/build.go:50` and
  `cmd/gdoc/publish.go:62` embed it as `body`.
- `skills/gdoc-publish/SKILL.md` has a Step 2 "Publish" and a Step 3 "Read the
  object back and say what it says". `skills/gdoc-export/markers.md` is the
  one table of what a marker in an exported file means.
- `docs/v2/MEASURED.md` has no row on Drive's import of run shading or of a
  run's text colour.

## Development Approach

TDD, one commit per task, the test first and failing. Every colour and every
emoji a test states is a literal. A task that finds the spec and the code
disagree stops and says so in the task log. `make test` keeps the race flag.
